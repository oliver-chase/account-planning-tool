# Accepted audit rows

Audit findings that were reviewed and not changed, each with its reason.

| Finding | Reason |
|---|---|
| One field and header list shared by import, export and the starter (`excel.js`, `start.js`) | The starter workbook is a deliberately smaller layout than the export, so the lists differ on purpose. The Plans columns and the field names are covered by the round-trip tests. |
| One section list for the call summary text and page (`call-summary.js`) | The two outputs differ in structure (plain lines against HTML blocks), and the saving is about 12 lines against a risk to both outputs. The call summary test covers each. |
| `singleSelectEl` and `popoverOptionsList` share list rendering | The two lists differ in search, selected state and keyboard order. Merging them saves about 8 lines and changes a shared picker used by every dropdown. |
| One save helper, one cycle check and one confirm-delete helper across People, Notes and Actions | The three save paths differ in what they stamp and re-render, and the cycle checks sit in different call contexts. People already share one delete helper, and merging the rest saves about 30 lines for a wider refactor. |
| `export.js` and `filterbar.js` merged into `app-shell.js` | Each has one job and one test or caller. Merging moves code without removing any. |
| `.card-meta-row--spaced`, the filter label rules and `.sort-select` written in more than one stylesheet | The copies have different specificity and the later one wins on purpose. A computed-style comparison is needed before any merge, for about 8 lines. |
| One grey token for the SVG icons | The search, sort and popover icons are data URIs that cannot read a custom property, and the greys differ slightly by design. |
| Undo for deleting notes and people | Deleting asks for confirmation and starts on Cancel, and notes and people carry linked data. |
| Moving a card with the keyboard has a visible hint and a picked outline, no Move button | The hint line and outline cover the path; a button per card adds visual noise. |
| Reviewing `ORG_EXPORT_CSS` against `accounts.css` | A standalone page needs its own CSS, and the export test checks the output exists and is static. |
| Note cards carry the group role, with no button role or `aria-expanded` | A card holds editable fields, so a button role would nest interactive controls inside a button. The group's accessible name says collapsed or expanded instead. |
| Focus after picking from a status, sort or owner dropdown | The dropdown trigger is rebuilt with its section. Weekday chips, pagination, filters and the org chart restore focus. Restoring dropdown triggers needs a stable key on every picker, for a narrow gain. |
| Shared test sandbox stub across test files | Each test needs a different set of stubs, so one shared helper would need options for most of them. |
| No CI workflow | Decided against: the PR workflows are off by choice. The pre-commit hook and `scripts/validate.sh` run the same checks. |
| `docs/CATALOG.md` lists generated rows only | The catalog covers scripts and config files. The test, hook and fixture scripts are described in the README table. |
| Catalog header names the audit generator | `docs/CATALOG.md` is generated by a tool outside this repo. Its Start column is empty because the catalog reads only a part's own first comment line. The README table says how each part starts. |
| Update Excel keeps no extra columns | Decided: Update Excel warns and names what the file loses, and does not merge columns it does not know. |
| A Done row with no ClosedDate is left out of the call summary's finished list | A row with no date cannot be placed in a week, and stamping one on import would count old work as finished this week. |
| Portability: the product name in index.html | The tool's own title matches the repository name, so the owner-identity check flags it. |
Accepted: owner-identity account-planning-tool.html
