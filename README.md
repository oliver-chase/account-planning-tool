# Account planning tool

One HTML file for running a recurring account call. It shows who is who, what is owed by when and what was said last time, and it keeps an Excel workbook current. There is no login, no server and nothing to install.

## Get it and open it

Download [account-planning-tool.html](../../releases/latest/download/account-planning-tool.html) from the latest release, which is rebuilt from the source on every change. It is one self-contained file with nothing to install, so it can be moved, renamed or emailed. Open it in Chrome or Edge. A new account offers three ways in: start a new account, open an Excel file, or try a sample account. Everything you type saves in the browser as you go.

## How a call goes

The How-to guide in the sidebar walks through a call: open the file, check who is on it, capture actions and notes, send the call summary and click Update Excel.

## The four sections

- **Plan:** the account's objective, strategy, revenue target, risks and review dates, plus meeting cadence and revenue
- **People:** cards and an org chart, where dragging a card onto another sets who reports to whom
- **Actions:** what is owed, with owners, due dates and Overdue and Due this week filters
- **Notes:** one note per call

The Plans and Revenue sheets hold the Plan page's fields and revenue chart. Update Excel replaces the file with the sheets and columns this tool writes. In Chrome and Edge it first names anything else in the file, and asks when someone saved the file in Excel since the tool last opened or updated it.

## Your workbook

Excel is the record. The start screen downloads a blank or sample workbook so you can see the layout: Overview, Plans, People, Actions and Notes sheets with plain names.

## Browsers

Chrome and Edge give the full experience: Update Excel writes into your workbook and the tool reconnects to it next time. Safari and Firefox work too, but Update Excel downloads a new file each time. The autosave lives in the browser, so a different browser or cleared site data starts without it until you save to Excel.

## Working on the source

You need Node and Python 3, and the WebKit run also needs macOS with the Xcode command-line tools. Run `npm install` once, then `bash scripts/validate.sh` to run the commit gates over every tracked file, every test and the build check. `python3 scripts/build-single-file.py` builds `account-planning-tool.html`, which git ignores. The release workflow builds it on every push to main and puts it on the latest release. `bash tests/webkit/run.sh` loads the built page in WebKit, the engine Safari uses, at six widths from 390 to 1280 px on a Mac. `DESIGN_SYSTEM.md` lists the components and tokens. Run `git config core.hooksPath .githooks` once per clone so each commit runs the gates and the validation first.

## Where things are

| Path | What it holds |
|---|---|
| `index.html`, `js/`, `css/` | The source: the page, the scripts and the styles |
| `scripts/build-single-file.py` | Builds `account-planning-tool.html`, the single file people open, from the source |
| `.github/workflows/release.yml` | Builds the single file on every push to main and replaces it on the latest release |
| `tests/`, `tests/fixtures/` | The Node tests, the simulated-browser test (`dom.js`), the WebKit run (`webkit/`), and a workbook that stores dates the way Excel does with the script that writes it |
| `tests/banned-words.local.txt` | Your own list of names that must never ship, one per line, kept out of git. Without the file the test reads a comma-separated `BANNED_WORDS` variable, and with neither it skips that check |
| `.githooks/` | The commit hooks, once `core.hooksPath` is set: `pre-commit` runs the shared gates on the staged files and then `pre-commit.local`, which runs `scripts/validate.sh`. `commit-msg` requires a story number and `pre-push` blocks a history rewrite or a secret |
| `scripts/validate.sh`, `scripts/size.sh`, `scripts/duplication_check.py`, `scripts/check-structure-contract.mjs` | `validate.sh` runs the commit gates over every tracked file, the structure check, every Node test and the build check. The line counter, duplicate-passage check and structure check are what the hooks and `validate.sh` call |
| `docs/SIZE-BASELINE.json`, `docs/EMOJI-GATE.json`, `docs/IDENTIFIER-GATE.json` | The size limit the pre-commit hook holds, and the files the icon and owner-name gates skip, each with a reason |
| `CLAUDE.md`, `QUALITY_BASELINE.md`, `docs/repo-structure-contract.md` | Rules for coding agents and how the repo follows the shared quality standard its hooks come from |
| `docs/CATALOG.md` | One row per script and config file, generated by an audit tool outside this repository from each file's own first comment |
| `docs/AUDITED.txt` | The audit ledger: each file an audit read, by its content hash, so the next audit reads only what changed |
| `docs/AUDIT-ACCEPTED.md` | Audit findings that were reviewed and not changed, with the reason for each |
| `docs/SHARING.md` | Whether the tool is shared, and what blocks a public copy |
| `docs/backlog-config.example.json` | Template for the local, git-ignored `docs/backlog-config.json` that a local backlog tool reads. The tool never reads either |
| `package.json`, `js/xlsx.full.min.js` | `package.json` lists jsdom, which only `tests/dom.js` uses. The script is SheetJS Community Edition 0.20.3, which reads and writes the workbook, bundled under the Apache 2.0 license (sheetjs.com) |
| `LICENSE` | MIT license for this tool's own code |
| `DESIGN_SYSTEM.md` | The components and tokens every section is built from |
